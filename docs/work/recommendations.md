# Nearby recommendations

Status: Phase 1 and place details complete (2026-10-23); phase 2 (Overpass) not started on `feat/nearby-recommendations`, branched from `feat/3d-map-poc` (needs the MapLibre map).

Goal: Repurpose the Map tab as a "Nearby" finder. Around a chosen stop or the map centre, list places of one category within an adjustable radius, and add any of them to the trip as an undated idea. Plan already shows each day's stops on a map, so the Map tab's whole-trip overview is dropped (ADR 0012).

Scope (phase 1): the Map tab, a pure `lib/nearby-places.ts` with Node tests, optional `nearby` props on `MapLibreMap`, and the tab label. Places come from the vector tiles' OpenMapTiles `poi` layer, which the map already loads: no new API, key, request, dependency, schema, API or persisted-format change. Plan's day map is unaffected.

Out of scope for phase 1: Overpass "Search more" (phase 2), querying off-screen stops without moving the map (phase 3), a "Find nearby" shortcut from Plan's stop rows (later, if wanted).

## Decisions (user, 2026-10-23)

- Tab label "Nearby"; the internal tab key stays `"map"`, so saved tab state and its shortcut keep working. The phone nav's "Places" slot reads "Nearby".
- Radius is a slider, not fixed: 200–1000 m in 100 m steps, default 500 m (about a 7-minute walk). The upper bound is set by the tiles: places exist only in zoom-14 tiles, so the camera cannot zoom out below 14 to fit a larger circle.
- Categories and OSM class mapping as E1 in `docs/work/3d-map-poc.md` proposed:
  - **Food** → item type `food`: restaurant, cafe, fast_food, bar, beer, ice_cream, bakery.
  - **Sights** → `sightseeing` (park → `activity`): attraction, museum, art_gallery, place_of_worship, theatre, park, castle, monument.
  - **Transit** → `commute`: railway, bus (bus stops included), ferry_terminal, aerialway, airport.
- Added ideas get a Google Maps link built from their coordinates, `https://www.google.com/maps/search/?api=1&query=<lat>,<lng>`. `app/api/maps/resolve/route.ts` reads coordinates back from the `query` parameter, so "Recalculate" keeps them.
- The whole-trip, day-filtered overview is dropped.
- Phase 2 (Overpass) is wanted later, called only on an explicit click.

## Design

Mockup: shown in the planning conversation (2026-10-23); the layout below is its description.

- **Browse (initial):** the Map tab's day list as before (All days and one row per day; shift-click selects several days on desktop; pills on phones). Picking days dims the others and fits their stops. A hint says "Pick a pin on the map to find places near it", with a "Search around the map centre" button. (User decision 2026-10-23: the "Around" dropdown was clunky, so the day list is back and a pin click picks the anchor.)
- **Search:** clicking any trip pin (dimmed ones included) makes it the anchor. The day list shrinks to a pills row; picking a day there returns to Browse. An "Around" card shows the pin's number, title and day, with "Details" (opens the inspector) and × (back to Browse, refitting the day). Below it:
  - **Radius:** a slider with its value ("500 m · about 7 min walk").
  - **Category:** Food / Sights / Transit segmented switch.
  - **Results:** rows with name, kind (OSM subclass), distance and walk minutes, and a "+ Idea" button. A saved idea is a trip item, so it drops out of the list by name or proximity; that is the "added" feedback.
  - **Footer:** "From OpenStreetMap. No ratings or opening hours; coverage varies."
- **Map:** the anchor stop pin highlighted, other trip stops dimmed, a dashed radius ring in `--accent`, and suggestion pins as small dots in the item-type colour. Hovering a row enlarges its pin and vice versa; clicking a pin scrolls to and highlights its row.
- **Phone:** day pills, then the map, then the hint (Browse) or the card, controls and list (Search).
- **Empty and partial states:** "Zoom in to see nearby places" when the map is below zoom 14; "Part of the radius is off screen, so some places may be missing" when the circle does not fit the view; "No food within 500 m" with a hint to widen the radius.

## Workstreams

Run by `sonnet` subagents. N1 and N2 touch different files and run in parallel; N3 needs both. The coordinator reviews each diff, re-runs the checks and updates this file; agents report in their final message and do not edit this file.

### N1 `lib/nearby-places.ts` and tests

- Pure, no MapLibre or React imports. Input: GeoJSON-like point features (`id`, `properties.name`, `class`, `subclass`), an anchor, a radius, a category, and the trip's mapped items.
- Keeps named features in the category within the radius; de-duplicates repeats across tile edges (same name and class within about 20 m); drops places already in the trip (same normalised name, or within about 30 m of a mapped item); sorts nearest first (the tiles' `rank` is ignored, user decision 2026-10-23); returns id, name, class, subclass, item type, lat/lng, metres, and walk seconds from `estimateWalk` in `lib/travel-legs.ts`.
- Exports the category list and mapping, the radius bounds and default, and `mapsSearchUrl(lat, lng)`.
- Tests in `tests/nearby-places.test.mjs`.

### N2 `MapLibreMap` nearby layer

- New optional props, so Plan's map is unchanged: `nearby` (anchor, radius in metres, suggestions, hovered suggestion id, `onHoverSuggestion`, `onSelectSuggestion`) and `onPoiFeatures(features, state)`. `onPoiFeatures` runs on `idle` with `querySourceFeatures("openmaptiles", { sourceLayer: "poi" })` and reports the zoom and whether the circle fits the view.
- Draws the radius ring as a GeoJSON polygon layer and the suggestions as small markers, styled with tokens.
- When the anchor or radius changes, fits the circle, clamped to zoom 14–17. N3 adds `fit: false` for Map centre mode (the anchor follows the map, so fitting would fight the user) and the map centre in the `onPoiFeatures` state.

### N3 Nearby view and wiring

- Rewrites `components/views/MapView.tsx` as the Nearby view (rail, slider, categories, list, states) using N1 and N2. "+ Idea" calls `openCreateItem(undefined, undefined, type, name, undefined, { name, lat, lng, googleMapsUrl })`, passed from `AppShell`.
- Tab label "Nearby" in `store/use-travel-store.ts` and the phone nav.

## Place details on click

Decided (user, 2026-10-23): clicking a result (row or dot) expands it with a short description, fetched on demand through a cached server route: OpenStreetMap element tags, then Wikidata's English description, then the English Wikipedia summary, with a Google Maps name search as the fallback link. No key or billing.

Research (10 Kyoto places): tile feature ids are OSM id × 10 + 1/2/3 (node/way/relation), confirmed for nodes and ways. OSM API 0.6 answers one element in about 0.2 s. All three shrines and one of two museums had a Wikidata English description; small places only had Japanese Wikipedia articles; four of five food places had cuisine or opening hours.

Contract: `lib/place-details.ts` (`PlaceDetails`, `decodeTileFeatureId`, `mapsNameSearchUrl`). `GET /api/place-details?type=node&id=123` returns `PlaceDetails`; 400 for bad input, 404 when OSM has no such element, 502 when OSM fails. Wikidata or Wikipedia failures leave their fields null rather than failing the request.

- **P1 route:** `app/api/place-details/route.ts` and server-only `lib/place-details-client.ts` modelled on `lib/parking-client.ts` (identifying User-Agent, per-request timeout, in-memory cache of 24 h and 500 entries, keyed by type and id), `api.placeDetails` in `lib/api-client.ts`, and Node tests of the pure tag-to-details parsing with fixture JSON.
- **P2 UI:** `NearbyPlace` gains `osmType`/`osmId` from the feature id; a row or dot click expands that row (one at a time) with loading, details, and error states; Wikipedia text shows its credit and link (CC BY-SA); listed hours are marked as possibly out of date; links to OpenStreetMap, Wikipedia and "Search in Google Maps" open in a new tab. Lookups run only on click, and the client keeps results for the session.

## Findings

- N1: ids are `class:name:lat5,lng5`, so they stay stable across idle reports; `walkSeconds` comes from `estimateWalk` and includes its 1.3 detour factor.
- N2: the ring is re-added on every `style.load` (theme switch, raster fallback) under `building-3d`; suggestion dots are DOM markers rebuilt only when the `suggestions` array changes, so the view must keep it referentially stable. The `fitKey` fit is skipped while `nearby` is set.

- N3 (superseded by the day menu): the anchor was a dropdown with a today-based default. Map centre mode uses the reported centre with `fit: false` and moves the anchor only after the centre moves 25 m. "Zoom in to see nearby places" covers both zoom below 14 and a viewport with no POI features (the raster fallback cannot be told apart from an empty area). The anchor stop is passed as `selectedItemId`, so its popup opens as on Plan.
- "+ Idea" saves the place at once (`openCreateItem` creates the item and opens it in the inspector); it is not a draft form.
- At zoom 14 a phone-width map fits about a 500 m radius; above that the "off screen" note shows.
